# План: Настройка JWT с гостевым токеном и ролевым распределением

## Проблема
- JWT-токен генерируется сервером, но клиент его **не сохраняет и не отправляет**
- `Home.razor` вызывает `api/Product/paged` (Admin-only) — неавторизованные получают 401
- Нет автоматического гостевого токена для анонимного просмотра
- `RegisterAsync` на клиенте вызывает Admin-only эндпоинт `api/User/create-student`

## Решение: 3-уровневая авторизация через JWT

| Роль | Доступ |
|------|--------|
| **Guest** (авто-токен) | Каталог (только чтение), изображения |
| **Student** | Каталог + заказы + профиль |
| **Admin** | Всё |

---

## Шаги реализации

### 1. Добавить роль `Guest` в `UserRole`
**Файл**: `CifraShop.Domain/Enums/UserRole.cs`
```csharp
public enum UserRole { Guest, Student, Admin }
```

### 2. Добавить эндпоинт гостевого токена в `AuthController`
**Файл**: `CifraShop.API/Controllers/AuthController.cs`
- Новый `[AllowAnonymous]` метод `POST api/Auth/guest-token`
- Генерирует JWT с ролью `Guest`, фиктивным Id=0 и email `guest@local`
- Не требует credentials

### 3. Разделить `ProductController` на публичную и админскую части
**Файл**: `CifraShop.API/Controllers/ProductController.cs`
- Убрать `[Authorize(Roles = "Admin")]` с класса
- Добавить `[Authorize(Roles = "Admin")]` на мутабельные методы: `CreateProduct`, `UpdateProduct`, `DeleteProduct`, `BatchDelete`, `BatchUpdateStatus`
- GET-эндпоинты (`all`, `paged`, `by-id`, `by-name`, `by-price`, `by-quantity`, `by-status`) — доступны всем авторизованным (включая Guest)

### 4. Разделить `UserController` — добавить профиль для Student
**Файл**: `CifraShop.API/Controllers/UserController.cs`
- Добавить новый метод `GET api/User/profile` с `[Authorize]` (любой авторизованный)
- Возвращает профиль текущего пользователя по claims из JWT
- Остальные методы остаются `[Authorize(Roles = "Admin")]`

### 5. Обновить `OrderController` — запретить Guest
**Файл**: `CifraShop.API/Controllers/OrderController.cs`
- Изменить `[Authorize]` на `[Authorize(Roles = "Student,Admin")]`
- Guest не может создавать/просматривать заказы

### 6. Обновить клиентский `AuthService` — сохранять и отправлять JWT
**Файл**: `CifraShop.Client/Services/AuthService.cs`
- Добавить поле `Token` (string?)
- `LoginAsync`: сохранять `AuthResponse.Token` в поле + в `localStorage`
- `RegisterAsync`: вызывать `api/Auth/register-student` (вместо `api/User/create-student`)
- Добавить `GetGuestTokenAsync()`: вызывает `api/Auth/guest-token`, сохраняет токен
- `Logout`: очищать токен, автоматически запрашивать гостевой токен
- Добавить `InitializeAsync()`: при старте приложения проверять localStorage, если есть токен — восстанавливать сессию через `api/Auth/me`, иначе — гостевой токен

### 7. Настроить `HttpClient` с перехватчиком токена
**Файл**: `CifraShop.Client/Program.cs`
- Заменить прямой `HttpClient` на `DelegatingHandler` (или inline через `IServiceProvider`), который добавляет `Authorization: Bearer <token>` к каждому запросу

### 8. Обновить `Home.razor` — инициализация гостевого токена
**Файл**: `CifraShop.Client/Pages/Home.razor`
- В `OnInitializedAsync` вызывать `Auth.InitializeAsync()` перед загрузкой товаров
- После инициализации токен уже будет в HttpClient

### 9. Обновить `Admin.razor` — проверка роли на клиенте
**Файл**: `CifraShop.Client/Pages/Admin.razor`
- Добавить проверку: если роль не Admin — редирект на `/` или показ ошибки

### 10. Обновить `Login.razor` — корректная обработка после входа
**Файл**: `CifraShop.Client/Pages/Login.razor`
- После успешного логина/регистрации токен уже сохранён в AuthService
- Навигация на `/`

## Проверка

1. `dotnet build CifraShop.slnx` — без ошибок
2. Запустить API + Client
3. Открыть `http://localhost:5001` — главная страница загружается с товарами (гостевой токен)
4. Войти как Student — видит каталог + может оформить заказ
5. Войти как Admin — видит всё, включая админ-панель
6. Выйти — автоматический гостевой токен, каталог доступен
