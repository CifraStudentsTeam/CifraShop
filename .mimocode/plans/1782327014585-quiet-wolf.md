# Plan: Исправления лаунчера, админ-панели и баланса

## Список проблем и исправлений

### 1. Лаунчер: ошибки SQL Server при первом запуске
**Файл**: `CifraShop.Launcher/Program.cs`
**Проблема**: При первом запуске Docker скачивает образ SQL Server (~1.5GB), это занимает время. Если download прерывается или SQL Server не успевает стартовать за 120с — миграции падают. При втором запуске образ уже скачан и всё работает.
**Исправление**:
- Увеличить таймаут ожидания SQL Server с 120с до 180с
- Добавить повторные попытки `docker compose up -d db` при неудачном старте
- Добавить проверку `docker compose logs db --tail 5` для вывода ошибок SQL Server при его неготовности
- При ошибке миграций — предложить повторить фазу 4 вручную из меню

### 2. Админ-панель: ошибки валидации не отображаются
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: API возвращает ошибки валидации в формате JSON (ProblemDetails или `{"errors":{...}}`), а клиент показывает сырую строку `await r.Content.ReadAsStringAsync()`. Пользователь видит JSON, а не понятное сообщение.
**Исправление**:
- Добавить вспомогательный метод `ExtractErrorMessage(string rawJson)`, который парсит ответ API и извлекает читаемые сообщения об ошибках
- Применить его во всех местах показа ошибок API

### 3. Товары: статус меняется, но метрики вверху не обновляются
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: `ToggleProductStatus()` меняет статус товара, но `_totalStockValue`, `_lowStockCount`, `_productTotalCount` не пересчитываются.
**Исправление**:
- После `ToggleProductStatus()` вызывать `LoadMetrics()`
- После `SetSelectedProductStatus()` вызывать `LoadMetrics()`
- После `OnQuantityChanged()` вызывать `LoadMetrics()`

### 4. Товары: добавление картинки сразу при создании (не должно быть)
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: `SaveProduct()` при создании нового товара делает `_editingProduct = created;` и оставляет модалку открытой с секцией загрузки изображений. Это неправильно — изображения должны загружаться только при редактировании существующего товара.
**Исправление**:
- В `SaveProduct()` для нового товара: после успешного создания закрывать модалку (`CloseProductModal()`) и обновлять список товаров

### 5. Товары: при редактировании не отображаются ранее добавленные картинки
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: `LoadProductImages()` загружает изображения через API, но URL изображений может не работать (проблема с относительными путями).
**Исправление**: Проверить корректность URL. Проблема в `ProductController.ToResponseWithUrl()` — он генерирует URL через `Url.Action("GetFile", ...)`, но если `ImageUrl` уже является полным URL, он не меняется. Нужно убедиться, что URL一致ны. Также проблема может быть в том, что при создании товара ImageUrl не устанавливается (см. п.4 — закрытие модалки решает это).

### 6. Товары: главная картинка отображается только после полной перезагрузки
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: После загрузки изображения через `OnImageUpload()`, URL обновляется только в `_editingProduct`, но в списке `Products` товар остаётся с старым ImageUrl.
**Исправление**:
- После загрузки изображения/установки главного/удаления изображения — обновлять `ImageUrl` соответствующего товара в списке `Products`
- После закрытия модалки товара — перезагружать список

### 7. Заказы: картинка перед номером — лишний элемент
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: В таблице заказов есть колонка с изображением (`<th style="width:2.5rem"></th>` + ячейка с картинкой). Для заказов нет смысла добавлять изображения.
**Исправление**:
- Убрать колонку с изображением из таблицы заказов (и `<th>`, и `<td>`)
- Убрать модалку управления изображениями заказа (`_showOrderImagesModal`)
- Убрать кнопку "Изображения" из развёрнутого заказа
- Убрать `OrderImage` связанный код (загрузка, удаление, set primary)

### 8. Заказы: при разворачивании нет информации о товарах и их картинках
**Файл**: `CifraShop.Client/Pages/Admin.razor` (развёрнутый заказ)
**Проблема**: В развёрнутом заказе показывается список товаров, но нет картинок товаров.
**Исправление**:
- Для каждого `OrderItem` в expanded view показывать изображение товара (нужно загрузить данные товара)
- Добавить поле `ImageUrl` в `OrderItemResponse` / API, чтобы получить картинку товара через OrderItem
- Или загружать данные товаров по `ProductId` из уже загруженных `_allProductsForOrder`

**Подход**: Использовать уже загруженный `_allProductsForOrder` — для каждого item найти соответствующий ProductDto и взять `ImageUrl`.

### 9. Товары: цена "уезжает вверх" из-за стрелок сортировки
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: Колонка "Цена" слишком узкая (`width:4rem`), стрелки сортировки не помещаются и теснят текст.
**Исправление**:
- Увеличить ширину колонки "Цена" до `5rem` или `6rem`
- Сделать стрелки сортировки компактнее (убрать или уменьшить)

### 10. Заказы: статусы сбрасываются после перезагрузки страницы
**Файл**: `CifraShop.Client/Pages/Admin.razor`
**Проблема**: `<select>` использует `value="@((int)o.Status)"` + `selected` атрибут. В Blazor `selected` на `<option>` конфликтует с `value` на `<select>`. При повторном рендере select может показать неверное значение.
**Исправление**:
- Убрать атрибут `selected` с `<option>` — Blazor корректно управляет selected через `value` на `<select>`

### 11. Баланс пользователя не списывается при создании заказа
**Файлы**: `CifraShop.Application/Services/Implementations/OrderService.cs`, `CifraShop.Infrastructure/Data/Repositories/Implementations/OrderRepositoryEfCore.cs`
**Проблема**: `CreateOrder` создаёт заказ, уменьшает количество товаров, но НЕ списывает баланс пользователя.
**Исправление**:
- В `OrderService.CreateOrder()`: после расчёта `totalSum`, проверить баланс пользователя (`user.Balance`), списать сумму
- В `OrderRepositoryEfCore.CreateOrderInTransaction()`: добавить обновление баланса пользователя в транзакции
- Если баланса недостаточно — выбросить `InvalidOperationException`

### 12. Консультация: разбиение Admin.razor на компоненты
**Решение**: Отложено. Разбиение Admin.razor на отдельные компоненты (ProductSection, OrderSection, UserSection, NotificationSection, MetricsBar) — правильный подход, но делается отдельной задачей после исправления багов.
